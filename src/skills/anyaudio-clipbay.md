# 剪辑台：把声音做成一份能被人继续编辑的工程

剪辑台不是「一个混好的文件」，是一份**多轨时间轴工程**。打开它的人会推推子、拖片段、试听、再让你改。你交出去的东西因此有两个层次：

- **素材**：真实的音频文件（WAV），进 `.anyaudio/projects/<id>/materials/`
- **工程**：说明每个素材放在哪、从第几秒到第几秒、多大增益的 JSON

工程文件永远是唯一事实来源，渲染只是它的纯函数。所以**你改的是字段，不是音频**：改完不用重新生成音频文件，剪辑台刷新就看到。

## 什么时候用剪辑台，而不是 `anyaudio_mix`

| 需求 | 用什么 |
|---|---|
| 对方要能自己调某一轨、挪某个音效、只重做一段 | **剪辑台 + 三个生成型工具** |
| 一段视频配一条完整混音，交付的是成品，之后没人会改 | `anyaudio_mix` |

判断标准很简单：**只要对方说过「这块能不能再…」「我想自己调一下」「只改这几秒」，就该用剪辑台；没说也一样**——人拿到文件后的第一反应通常是「某一处能不能改改」。60 秒以上的多轨内容默认也用剪辑台，返工成本比一次性混音低得多。

**默认就建工程。** 凡是要产出一段有人会听的东西（配音、音乐、音效、视频配乐），先建工程再生成素材。人打开剪辑台才能听见结果、才知道能不能调；只给一堆文件路径，等于让人对着一串文件名想象声音。

这不是靠自觉：`anyaudio_music`、`anyaudio_tts`、`anyaudio_sfx` **都要求传 `projectId`**，不传直接报错。所以顺序是死的——先 `create` 拿 id，再生成。

`anyaudio_mix` 不是剪辑台的替代品：它把成品压成一条混音，做不了单轨调整。已经建了工程还去调 `anyaudio_mix`，等于把人能调的那层信息丢了。

建工程不用问过用户——它建在 `.anyaudio/projects/` 下，不覆盖任何既有文件。名字用内容本身命名（「海边主题曲」「第三集旁白」），不要用「untitled」或时间戳。

## 建工程的标准流程

```
1. anyaudio_project({ mode: "create", name: "海边主题曲" })
      → 返回 projectId，例如 prj_ab12cd34

2. 三个生成型工具都带上 projectId，素材自动入工程、自动建轨、自动落片段：
   anyaudio_music({ projectId, score, stems: true })   ← 每条 stem 各占一轨
   anyaudio_tts({ projectId, text, items: [{ text, voice }] })   ← 同一音色归到一轨
   anyaudio_sfx({ projectId, items: [...] })  ← 每个音效一个片段，自动落轨

   用户自有文件（他给的 MP3、要用的素材）才走 add_material：
   anyaudio_project({ mode: "add_material", projectId,
                      sourcePath: "<文件>", kind: "music",
                      trackName: "外部音乐", category: "music", startSec: 0 })

3. anyaudio_project({ mode: "read", projectId })   ← 改之前先读
4. anyaudio_project({ mode: "update", projectId, changes: [...] })
5. anyaudio_project({ mode: "render", projectId, format: "mp4" })
```

**素材文件落在哪**：生成型工具先把音频写进 `.anyaudio/out/`，再复制一份进 `<工程>/materials/`——这份是工程真正播放的副本。你传 `output` 只是额外再复制一份到用户指定的位置，工具会把两个路径都报出来。所以用户的原始文件永远不会被搬走或删掉。

`add_material` 一次只登记一个文件，但会顺手把轨道建好、把片段摆上去。**不要**先建一堆空轨道再往里塞。

音效走 `anyaudio_sfx`：一次拿到 N 个各自从 t=0 开始的短文件 + 一份带「类别」的清单，每个文件同时落成工程里的一个片段。**它没有"把整段音效烤成一条"的模式了**——那种产物里每个声音都没法单独挪动，等于白建工程。

## 分轨规则（必须遵守）

这是 spec §5.2，不是建议：

1. **一个素材一条轨**，不要为了省轨把不同素材混进同一条
2. **乐器 STEM 各自成轨**（鼓 / 贝斯 / 钢琴），不要合成一条「配乐」——人要能单独把鼓推上去
3. **旁白按音色归集**，`category: "tts"`：同一个音色的所有台词落在同一条轨上，哪怕两句重叠；换一个音色就多一条轨。要按角色分轨时用 `trackName` 显式起名
4. **环境音与动效分开**（`ambience` / `foley`），雨声和开门声不是一类；同类里时间重叠的自动再开一条（`音效 · 动效 2`），不重叠的合并
5. 轨道总数上限 **20**，总时长上限 **15 分钟**——超了会被拒绝，别硬凑

轨道名用人能看懂的中文。「轨道 3」这种名字等于没起。

## 保留创作资料

`add_material` 会冻结一份快照到工程的 `sources/` 里。**快照不要删、不要改**：它是「这个素材当时是怎么做出来的」的唯一记录。重做一段时，你要么用同一份快照重新生成，要么把新素材作为新材料加进来——不要覆盖旧素材，人可能想比较两版。

生成型工具（`anyaudio_music` / `anyaudio_tts` / `anyaudio_sfx`）入工程时也会自动冻结快照：music 存整份 score，tts 存文本、引擎与音色，sfx 存 preset 或程序化参数与 seed。

## 人让你改一段的时候

人的消息里会带一段 `<anyaudio-timeline>` 上下文，写明工程、轨道、片段、时间范围，以及**范围内现在有哪些片段**。

规矩只有一条：**只动被点到的范围，其他轨道和片段一个字段都不要碰。**

```
anyaudio_project({ mode: "read", projectId })      ← 先看现在的样子
  ↓
anyaudio_project({ mode: "update", projectId, changes: [
  { target: "track", trackId: "trk_01", field: "volumeDb", value: -3 },
]})
```

`update` 的每一次调用都会追加一条 `by: "agent"` 的变更记录，人看得见你改了什么。**人不能撤销你的改动**（spec §9.5），所以改得越窄越好。

如果他说的范围里没有你想要的素材，先 `mode: "add_material"` 生成新的，再改引用——不要凭空改一个不存在的片段 id。

## 不要做的事

- **不要自己算时间轴混音**。工程是数据，`mode: "render"` 会做叠加、增益、淡化、声像。
- **不要自己调 ffmpeg 拼成片**。成片必须由 `anyaudio_project mode:"render"` 产出：自己 `-c:v copy` 拼出来的 MP4，剪辑台里看不到画面，工程和成片从此各说各话。插件拦不住你，但那就不是「交出一个能继续编辑的工程」了。
- **不要在工程里加「版本号」「锁」「并发标记」**。规格明确不做这些（spec §9.2）：人和 Agent 一轮一轮来，不并发。
- **不要把播放头、选区、缩放写进工程**。那些是界面状态，不是工程内容（spec §6.8）。
- **不要归一化到 -1.5 dBFS 之后再交出去**。归一化只在初稿做一次，写在 `normalizeGainDb` 里固定；导出时再算一次会把人调的音量抵消掉（spec §10.2）。

## 与视频整合

**画面必须先于 render 进工程。** 画面不在工程里，`format:"mp4"` 会直接拒绝——那时唯一的正解是把画面导进来，不是自己拼。

两条分支都通向同一个终点（工程里有画面、有声音，`render` 出成片）：

| 起点 | 顺序 |
|---|---|
| **先有画面** | `add_material` 导入 MP4（抽原声、建轨、置 `project.video`）→ 音乐 / 旁白 / 音效 → `render` |
| **先有声音** | `create` 建工程 → 音乐 / 旁白 / 音效 → 调轨 → 做好画面 → `add_material` 导入 → `render` |

导入视频时插件会把它的音轨抽成 `video-audio` 素材并自动落轨，工程从那一刻起有画面了；结果文本会明说这一点。

## 导出

```
anyaudio_project({ mode: "render", projectId, format: "mp4" })
```

- `wav` 默认，`mp3`、`mp4` 可选
- `mp4` 只对带参考画面的工程有效（`project.video` 存在时）；没有画面时错误信息会告诉你怎么把画面导进来
- 画面比声音长时，成品保留完整画面长度，声音补静音

渲染完把 `file` 路径告诉人，别自己再压一遍。
